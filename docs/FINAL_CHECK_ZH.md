# 开源前最终检查（2026-11-17）

检查对象是这个独立开源副本。原项目、服务器代码、冻结配置和历史实验结果未改动；修改前副本已另行归档。代码与文档采用作者确认的 **MIT** 许可，第三方组件和外部数据保留原条款。本轮没有发布到公共仓库。

## 名称与方法边界

- 系统 **GReDAC**、结构 **RDF**、Python 包 **`gredac`**。六个旧名辅助模块及七个自有环境变量已统一；导入、进程入口、计时标签、A2A 补丁和校验清单同步修改。
- 最新论文的固定接收端符号为 **G**，早期 B 是同一角色的旧称。四阶段与实际函数、网络入口、局部夹具的对应关系见 `METHOD_MAPPING_ZH.md`。
- 未使用的自写 `native_*` 对照移出本副本；SAGA 对照仍执行固定 commit 的作者源码，99 个归档文件逐一校验。SAGA 不改称 GReDAC。
- 历史认证格式、密码域分隔和证明证书的标识保留原字节，并在 `NAMING.md` 解释；它们不是当前系统名。未为更名修改协议消息、安全检查、事务顺序或 WAL/FULL。
- 原说明中的局部 MemoryBIO/逻辑时钟演示与当前独立进程 TCP/TLS 路径明确区分。A2A 是独立副本中的受控 SDK 桥接，并非完整公共 A2A 服务实现。

## 修复的可运行性问题

1. 补齐 RQ3 离线回归依赖的 `FEASIBILITY_TEST_ONLY.json`。只有离线测试读取它；正式模型入口不读取测试答案。
2. RQ2 的计划回归改为检查当前第一组 36 次矩阵；RQ4 回归检查当前 39 次固定矩阵，A/B 独立入口默认最大服务数为 256。旧 RQ4 调度 CLI 明确禁用，避免误跑旧矩阵。正式矩阵本身没有扩展。
3. 补上旧版 Z3 Python 绑定实际依赖的 `setuptools==68.1.2`，解决全新 Python 3.12 环境缺少 `pkg_resources` 的错误。
4. A2A 辅助检查直接读取用户指定的已完成回归目录，按该回归的实际调度参数检查证据完整性，取消对旧目录名和固定 61 条记录的隐含依赖；默认大规模参数不变，允许明确指定有界验证参数。
5. wheel 仅安装核心库；实验从包含输入和冻结清单的源码目录运行，避免安装一个缺少输入文件的半成品实验包。验证了 wheel 的构建、安装及目录外导入。

使用全新隔离 Linux/WSL 目录、Python 3.12.3；基础运行依赖 cryptography 41.0.7，RQ2/证明环境使用相应锁定依赖，A2A 使用 SDK 1.3.0 的独立环境。服务器 SSH 在本轮拒绝连接，因此这些是本地功能 QA，**不是服务器复测或新论文性能数据**。所有入口串行运行各自负载；不同 QA 套件的时长不用于性能比较。没有真实 LLM/API 任务调用。

## 保留的失败与限制

- 初次裁剪缺测试夹具、证明环境缺 `pkg_resources` 的错误均有记录；修复后相应检查通过。
- 大规模 A2A 随机调度 QA 在外部 900 秒上限被中止，**未记为通过**。随后使用明确有界参数完成 B1–B4、故障与辅助检查；这不替代完整的大规模竞争测试。源码中仍可显式运行更大的原始调度参数。
- 一次自编 QA 输入把“额度规模”实验的固定深度错设为 2，触发结果检查；该失败保留，使用原计划要求的深度 4 后通过。没有修改正式参数或绕过检查。
- 首次尝试关闭构建隔离时发现本地比较环境没有构建后端；使用声明的隔离构建依赖后 wheel 构建与安装通过。
- 本轮未运行真实 LLM、完整性能矩阵或真实跨主机部署，不重新估计任务完成率和性能；没有对外发布。

完整 QA 日志、失败、状态和隔离副本保存在内部验证归档中，不把测试私钥、数据库或新增性能样本装入开源包。原论文数据仍在原归档。本包已有的数据范围见 `DATA_INVENTORY_ZH.md`。

## 使用者自检

先按 `REPRODUCE.md` 安装依赖，在 Linux 源码根目录执行：

```bash
python tools/check_release.py
python tools/test_release.py --out results/release-check --check-only
python tools/test_release.py --out results/release-check
```

每次选择新目录。可选 A2A 和证明组件按各自 README 安装与验证；公共回归不会自动启动这些组件、真实 LLM 或正式实验。
