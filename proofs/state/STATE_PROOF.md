# GReDAC: parameterized endpoint-state proof

This is a new state model of the frozen v1.2 specification in `../inputs`, not a renamed v2/v3 Authority, lease, UTXO, or new-anchor model. It proves the state part of P2–P4. Cryptographic origin, confidentiality, key exposure, RDF closure, and tag unforgeability are premises supplied by the separate cryptographic analysis; they are not conclusions of this file.

## 1. Semantic interface and trust boundary

`kernel.py` represents one authoritative receiving endpoint G, with arbitrarily many sources, authorizations, capability nodes, ownership records, and requests. A source's G, context, anchor, capacity and root authorization are immutable after declaration. Every unit is the permanent pair `(source, position)`, with `0 <= position < N_source`. No operation mints a replacement unit during recovery or service replacement.

Each transition returns `(guard, provisional_post_state)`. A successful durable atomic commit requires the entire guard. A failed guard retains the entire original state. The caller must not publish provisional intermediate rows. Atomicity, durability, prevention of state rollback, nondecreasing protocol time, and the fixed authoritative G assumption are protocol assumptions. They are not proved properties of a database, clock, network, or implementation here.

There is deliberately no clock variable or separate `retired` bit in the kernel. A trace supplies `now` arguments in nondecreasing order. An expired unused unit is abstractly retired by retaining its unchanged/shrinking `hard_until` and requiring `now < hard_until` for every future activation, admission, and recovery candidate. Its ineligibility follows from these guards, deadline monotonicity and the trace-time premise together. The proof does not cover a caller choosing arbitrarily decreasing `now`, nor claim an explicit physical retirement transaction. Source blocking is a separate permanent flag checked by admission/activation; it is not a clock theorem.

`authentic`, `approved`, `authorized`, `tags_valid`, and `contact_guard` are typed verification interfaces, not statements that all adversarial messages are valid. An accepted real message refines a transition only after the corresponding signature, approval, contact, tag, participant and canonical-parsing checks succeed. This model proves consequences conditional on those checks; composition must justify those interfaces using the cryptographic model. Ordinary authorized malicious members remain able to propose any values satisfying their actual scope and the state guard.

The immutable authorization/capability catalogues are proof ghosts for *parsed, structurally validated descriptions*, including descriptions still offline. Appending a catalogue row is not activation, not a balance transfer, and not a TAM interaction. Authorization and capability identifiers are injectively renamed to increasing natural catalogue indices. Public-ID freshness and immutable descriptor binding are parser/cryptographic obligations. The catalogue count is unbounded; the index order makes every particular parent chain finite without fixing its maximum depth.

`registered_prefix` is specifically a previously registered **nonroot delegation-description** prefix. It checks `right_record[d] = ell`, exact stored control-message bytes, and live dependencies, and stutters. Initial issuance and root authorization are different typed records: a root may authorize more than one source. Similarly, `cancel` accepts an authenticated authorized cancellation of a **delegation-description ID**, possibly still offline. It is not a generic cancellation API for initial-issuance or recovery record IDs. Tombstones and descriptor-ID cancellation are retained, never cleared.

The request datatype contains the request ID, context, session, both principals, both authorization IDs, action, complete payload string, and the source-indexed vector `(unit,anchor,capability,ownership-record)`. Its equality checks every scalar, the exact source domain, and every vector member in that domain. Array values outside the domain have no wire representation and are ignored. The refinement parser must accept only a finite canonical vector with no duplicate sources. The ACT binds the participants, authorization IDs, context, session and deadline; it does **not** bind payload or action. Those latter bindings are request/tag obligations. `record_body` is exact canonical control-message bytes, not an assumed collision-free integer fingerprint; the typed parser must bind these bytes to the supplied descriptor fields.

## 2. State invariants

Write `Anc(d,a)` for a reflexive authorization ancestor and `CAnc(c,b)` for a reflexive capability ancestor. The following invariants are checked from the empty initial state and preserved by every primitive transition.

1. **Authorization forest.** Every authorization has one earlier parent or is a root. Context and side are inherited. Action permissions and deadline only narrow; remaining delegation depth strictly decreases. `Anc` is exactly the recursive parent closure, is transitive, and the ancestors of any node are comparable. Both caller and service forests satisfy the same invariant.
2. **Source consistency.** Every issued source is known. Its finite capacity is nonnegative and its root is a caller-side root in the same context. This prevents declaring a previously unknown source from silently activating spent or issued rows.
3. **Capability/authorization correspondence.** A capability has the same source and anchor as its ancestors. Its holder is a caller authorization in that source's context. A child capability's parent is held by the immediate authorization parent. Capability scope is a relation of `(permanent unit, action)`, narrows along the capability history, and is within its holder's authorization. For **every authorization ancestor d of a capability holder**, `cap_at[c,d]` names an existing capability ancestor held by d. This is a proved invariant, not an arbitrary recovery selection guard.
4. **Registration closure.** A registered capability and all its capability ancestors exist and are registered, and its authorization holder is registered. Cataloguing a child capability does not satisfy this condition.
5. **Unit consistency and conservation.** Each issued permanent unit has one current capability, holder and used ownership-record ID. The capability has that source and anchor and is registered. The hard scope H is contained in its current capability's scope; the hard deadline is no later than its holder's deadline. For every unit, `0 <= charges <= 1` and `spent iff charges = 1`. Unissued units have zero charges and are unspent.
6. **Decision-to-debit correspondence.** A recorded decision stores its own request ID and original caller. An accepted decision has exactly one first-delivery marker. Every required permanent unit named by that decision is issued, spent once, and names that request as its unique charging request. Rejected decisions have zero first deliveries.
7. **Debit-to-decision correspondence.** Every spent unit refers to an accepted recorded request which selects that unit. There are no orphan debits.

In addition, all operations preserve spent bits, used-record bits and revocation bits monotonically. Once a unit has been issued, its hard scope never widens and its hard deadline never increases. These temporal strengthening obligations are checked separately rather than inferred from a snapshot invariant.

## 3. Construction and inductive proof

Let I be the conjunction of the seven universally quantified invariants. For every transition T, the verification conditions establish

`I(S) and guard_T(S, parameters) => I(post_T(S, parameters))`.

The empty initial state satisfies I. Therefore I holds after every finite sequence of commits, for any finite number of sources, nodes, units per source, requests, and arbitrary finite delegation depth. This is ordinary induction on the number of committed transitions. No finite trace length or bounded identifier universe appears in these preservation obligations.

`verify.py` uses arbitrary symbolic test indices, then generalizes them universally. To avoid incomplete SMT quantifier search, `ground_facts` supplies explicit instances of the *pre-state* universally quantified invariant. Every instance is generated by the same `right_fact`, `tree_fact`, `source_fact`, `cap_fact`, `registered_fact`, `unit_fact`, `decision_fact`, or `charged_fact` function defining I. No post-state invariant is assumed and no invariant is added to an operational guard. Proving the claim from these finitely many logical consequences proves it from I; the number of instantiation terms is not a bound on the protocol population.

The preservation argument by transition is as follows.

* Root/child catalogue append changes only one fresh metadata row and increments its count. An earlier parent chain cannot contain the new index. The new authorization ancestor row is its parent's row plus itself; the new capability ancestor and `cap_at` rows are constructed likewise. Parent narrowing yields transitive narrowing; the existing forest lemma yields ancestor transitivity and comparability. No unit, debit or decision changes.
* Source declaration changes one previously unknown source. `issued => known` ensures that this did not previously denote any issued source. Initial issuance is allowed once, on a declared source and its root capability, with a fresh record. It initializes ownership/H/deadline of precisely that source's permanent units. It does not reset any spent or charge field.
* `sync_group` handles one **whole signed description**, potentially spanning multiple sources. Every selected unit must still be unspent, known, unexpired and owned by the described immediate parent with the exact predecessor record. The target capability's parent equals the actual current capability, not merely an advertised parent. Every unit covered by each target capability must be selected with that same target. Commit transfers all those rows, registers the child, and narrows H/deadline. The same authorization cannot be activated twice. A conflicting description loses its CAS after a competing transfer; disjoint valid descriptions remain possible.
* The registration proof splits the exact postcondition `old_registered(c) or exists selected u with target(u)=c`. In the old case registration is monotone. In the new case eliminate the existential using an arbitrary selected witness u: the guard supplies the actual registered predecessor, and capability ancestry supplies all older registered ancestors. `sync_group_registered_new` proves this case using the lower-bound registration array `old_registered(x) or x=target(u)`; the actual registration array contains it. `sync_group_registered_old` proves the old case. This explicit existential-elimination argument connects those two VCs to the full invariant; it is not a bounded witness search.
* `sync_service` registers the service authorization and its record without modifying any caller-unit field. A registered prefix is a stuttering step. Fresh ACT/contact creation outside this state abstraction also changes no caller-unit field.
* `admit` requires both complete live authorization paths, actual participant bindings, ACT binding, the exact required-source domain, and each vector element's current capability/record/anchor, H, scope, deadline and unused status. It sets spent, increments charges by exactly one on selected units, and atomically records the accepted request and first-delivery marker. Selected units were unspent, so the induction hypothesis makes their old charge zero. Every other unit is a frame case. Old accepted requests cannot refer to a newly selected unit: their invariant would make that unit already spent. This preserves the full decision/debit bijection.
* `reject` only records a fresh rejected decision; `retry` checks the exact recorded request and original authenticated caller and stutters. Retrying a recorded operation never reevaluates new-admission authority, debits units or creates another first delivery. Reject is deliberately permitted even for otherwise valid requests: the model proves safety, not an unfair scheduler's liveness. The constructive legal traces establish nonvacuous admission and reuse.
* Revocation and delegation cancellation only add permanent tombstones. Recovery changes current capability/holder/record of precisely eligible unused descendants; all cryptographic metadata, source anchor, H, hard deadline, spent bits, debit records, decisions, revocations and cancellations are frames. Context/source blocking and usage-unknown marking cannot create authority or debits.

`sync_batch` folds an arbitrary finite list of these provisional transitions and conjoins every step guard with the bilateral contact/path check. Mathematical induction on the list length lifts primitive preservation to arbitrary-length batches. A successful outer commit exposes only the final state; failure exposes the original state. Already registered prefixes stutter. This proves all-or-none activation and full-description transfer under the stated transaction assumption, rather than proving a particular database implementation atomic.

## 4. Security consequences

### P2: current bilateral eligibility and linearized activation

New acceptance implies both caller and service authorization chains are registered, unrevoked, uncancelled, in the context, in scope and before all relevant deadlines. The supplied principals must equal the authenticated participants and the current authorization holders. The required sources are exact; every vector element selects its current permanent unit/capability/record/anchor. CAS links activation to the prior actual state. The ACT and cryptographic checks must be supplied by composition, so none of these state assertions is called cryptographic unforgeability.

For any endpoint commit order, two descriptions trying to transfer an overlapping unit from the same old ownership state cannot both activate: after the first, either the holder/capability/record is different or the child is already registered. Once that unit returns to the old parent capability, the fresh return record keeps the old predecessor record unequal. This is the relevant ABA protection; it is not a new anchor or a new permanent unit.

### P3: exact accounting, no double charge and retries

For every source s, let `U_s = {(s,i) | 0 <= i < N_s}`. Unit consistency gives a function `charges: U_s -> {0,1}`. Therefore `sum_{u in U_s} charges(u) <= N_s`. Decision/debit correspondence maps each accepted required-source debit to one selected permanent unit and a unique request. This cardinality argument is a mathematical corollary of the parameterized unit invariant, not a bounded SMT enumeration of a particular N_s.

The source-indexed request vector selects one unit for every and only the required sources. Since the pair's source equals its vector index, different sources cannot alias the same permanent unit. `admit_exact_debit` states the exact per-unit delta. Conservation continues across every transfer, return and replacement because charges and spent are never reset. A second fresh request with an already spent unit fails; the same request ID cannot obtain a second new acceptance; an exact retry returns the recorded decision without another debit or first delivery. These are at-most-once *admission/first-delivery-marker* guarantees, not proofs of exactly-once external business side effects or guaranteed network delivery.

### P4: subtree revocation, exact recovery and nonresurrection

After the target's revocation commit, every registered descendant's `rlive` is false because its ancestor closure includes that target. An unregistered, authenticated described target can also be tombstoned without transferring anything; later activation checks the same tombstone, and a descendant cannot obtain a live parent chain. This relies on immutable ID/descriptor binding from the cryptographic interface. With monotone endpoint time, expiration also cannot be undone by moving a unit.

For a recoverable unit u held below target t, define the eligible strict-ancestor set E from initial source policy and current live authority. This set is finite: ancestors have strictly smaller nonnegative catalogue indices. If E is nonempty, its nearest member exists (take the greatest/deepest member) and is unique because the ancestor chain is comparable. `nearest` expresses exactly this choice and excludes every closer eligible member. If E is empty, the unit stays blocked under the revoked branch, representing escrow; no valid new admission can spend it. Unknown usage is not recycled, spent units are excluded permanently, and expired units are not returned. Root revocation has no ordinary ancestor recovery transition.

It remains essential to establish that the chosen ancestor has a capability corresponding to this *particular unit's actual history*. From `Anc(current_holder(u),t)` and `Anc(t,P)`, the proved forest lemma gives `Anc(current_holder(u),P)`. Unit consistency identifies `current_holder(u)=holder(current_cap(u))`. The proved `cap_at` invariant supplies the existing capability `cap_at[current_cap(u),P]`, held by P and on that exact capability history. Registration closure makes it registered; capability narrowing gives `H(u) subset scope(old_current_cap,u) subset scope(return_cap,u)`. Authorization narrowing gives the compatible deadline. Thus recovery restores a legitimate prior parent capability and does not rely on an unproved arbitrary-capability selection guard. This reasoning applies independently to each source and capability group.

Recovery preserves the original anchor, H, hard deadline, spent bits and historical decisions, and installs a fresh used record. Old descriptions name the former record and cannot activate after return. Old descendant authorizations remain revoked; possessing historical descendant keys cannot make them live. The state theorem does **not** claim that the parent lost its retained derivation seeds, or that old keys cannot derive fresh siblings: that exposure-sensitive statement is the RDF theorem. Repeating the same recovery record fails freshness; another recovery over the same branch cannot return the already moved unit again, because its holder is now a strict ancestor of the revoked target. A later legitimate delegation/revocation cycle may return the same still-unused permanent unit again.

## 5. Evidence and reproducibility

Run from the repository root:

```text
python proofs/state/verify.py --timeout-ms 8000
python proofs/state/witnesses.py
python proofs/state/replay.py
```

`RESULTS.json` records 317 successful UNSAT obligations: initialization, all primitive preservation cases, temporal monotonicity and direct consequences. `smt/` contains their standalone SMT-LIB; only names in the manifest are current evidence. Older exploratory query names may remain in that directory and are not counted. `WITNESSES.json` records three SAT legal traces, four UNSAT attacks against the original rules, and four SAT negative controls. These are finite nonvacuity and mutation checks, **not** the proof of arbitrary depth/population. The negative controls intentionally remove spent, revocation, predecessor-record CAS, or exact retry-message checks, respectively; none is a counterexample to the original model. The legal traces use the same kernel transitions as the induction proof and include caller and service delegation, admission, same-anchor parent-capability return, fresh-record regrant and new consumption.

`REPLAY.json` records a separate OS process of the external Z3 executable for every manifest-listed query and verifies each formula's SHA256. This is independent replay of generated formulas, not independent verification of Z3's internal proof calculus. Trust remains in the frozen specification-to-model correspondence, the Python formula generator, mathematical induction/finite-chain arguments above, SMT-LIB parsing, and Z3 4.8.12. Quantified SMT is incomplete in general; UNKNOWN and SAT for a claimed validity obligation are failures, never treated as proof. Explicit valid instantiation resolved the exploratory timeouts without adding safety conclusions as transition guards.

The mechanically checked level is an unbounded symbolic state-transition induction with arbitrary array indices. It is neither a tool-generated proof of implementation refinement nor a proof of computational cryptographic security. The paper should cite the separate composition and crypto proofs for those distinct obligations and state these boundaries explicitly.
