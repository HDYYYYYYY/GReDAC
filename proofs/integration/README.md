# Joint executable witness and mutation controls

Run `python integration/witness.py` from any working directory. It imports
`../state/kernel.py` directly and applies those exact transition expressions;
there is no second independently implemented ledger hidden in the witness.
It also imports `../crypto/reference.py`, uses its actual restricted initial
bundles, recursive reconstruction and canonical byte encoding, and verifies
SHA-256-derived tags at each current admission state.

The concrete trace includes two caller and two service delegation levels, two
required sources with four permanent units each, reused contact/session
bindings for dialogue chunks, an exact retry, compromised-parent/child
known-key behavior, mixed-message tags, cascading caller revocation, exact
return under the original anchor, stale predecessor rejection, preservation
of narrowed restrictions, replacement caller delegation, and independent
service replacement. Four successful admissions consume four units per
source. Rejected attacks and historical decision lookups add no consumption.
The trace uses a monotonically increasing logical clock.

At admission the driver re-encodes the mathematical message into the very
bytes authenticated by RDF, reconstructs keys from the **current** state,
and verifies supplied tags and ACT signature. It does not carry forward a
cached `tags_valid` result. The mixed-tag attack supplies the mixed bytes; a
negative boolean is not simply stipulated. Unencoded array entries are
explicitly tested not to change canonical-request equality for retries.

Mutant checks deliberately ignore a signed preceding-record field or erase
persistent inherited restrictions. Those weakened checks enable the attacks
that the actual transitions reject. The leaked-parent check shows why new
public Grant identifiers do not repair a disclosed parent secret. These are
small finite necessity controls, not claims that empirical unsuccessful
attacks establish cryptographic security.

`RESULTS.json` records individual solver outcomes and input/code hashes.
`queries/` contains the exact SMT-LIB queries generated by the finite witness;
`unsat` means the negation of an expected-enabled guard (or the guard of an
expected-rejected attack) has no model. Only filenames listed in the current
JSON are the current witness evidence; intermediate queries may be retained
after an audit-driven revision and are not included in current counts.

## Explicit limits

This trace has fixed sizes. The arbitrary-size claims come from the
mathematical induction and state VCs, not from this trace. Its Ed25519 fixtures
are public test keys. The control-description encoding is a finite functional
profile; protected approval/descriptor authenticity and the authenticated
channel are supplied through the state model interfaces. The witness does not
implement all wire parsers, the registration PKI, TLS, crash recovery, or the
production stack. In particular it must not be cited as a mechanically proved
implementation refinement. The unbounded same-request abstraction and its
interfaces are stated separately in `../COMPOSITION_PROOF.md`.
